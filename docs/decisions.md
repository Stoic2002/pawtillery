# Design & technical decisions

Decisions not spelled out in the PRD. Simplest option chosen, logged here.

## M0 — Project foundation (2026-10-18)

- **Flutter SDK pinned to 3.41.7** (fvm, matches `.metadata`). `tool/ci.sh`
  falls back to `~/fvm/versions/3.41.7/bin/flutter` when `flutter` is not on PATH.
- **Removed `cupertino_icons`** — not in the PRD package list.
- **Landscape lock** in two places: `android:screenOrientation="sensorLandscape"`
  (no portrait flash at launch) and `SystemChrome.setPreferredOrientations`.
  Note: on API 36, Android ignores orientation locks on large screens
  (sw ≥ 600 dp); phones are unaffected. Layout must still tolerate it.
- **Immersive sticky** system UI for the whole app (game feel, edge-to-edge
  is mandatory on API 36 anyway). Screens wrap content in `SafeArea`.
- **Locale resolution:** device language `id` → Indonesian, anything else →
  English. `PawtilleryApp(locale:)` overrides it (tests now, Settings in M4).
- **PRNG: mulberry32** (`lib/sim/rng.dart`). 32-bit integer math only, pinned
  by a test against the canonical JS reference values. State is a single int,
  so snapshots are trivial.
- **State hash: 32-bit FNV-1a** (`StateHasher` in `lib/sim/world.dart`), not
  `Object.hash`, because `Object.hash` is seeded per process and would differ
  between runs.
- **Fixed timestep:** accumulator in `PawtilleryGame.update`, max 5 sim steps
  per frame; if still behind after that, the backlog is dropped rather than
  queued (avoids spiral of death).
  The sim never sees `dt`.
- **Sim purity guard:** `test/sim/purity_test.dart` fails if anything in
  `lib/sim/` imports Flutter/Flame/`dart:ui`/`dart:io`, calls `Random(`,
  `DateTime.now(`, `Stopwatch(` or a libm function (`sin`, `cos`, `pow`, ...).
- **ARB parity test** (`test/ui/arb_parity_test.dart`): EN and ID must have
  the same keys.
- **Asset folders** exist with `.gitkeep` but are not yet registered in
  `pubspec.yaml`; each is added once it holds a real file.
- **Application ID left as `com.example.pawtillery`.** It is permanent once
  uploaded to Play and Play rejects `com.example.*`, so it must be chosen
  before M6. Open question for the owner.

## M1 — Terrain and projectile (2026-10-18)

- **Whole-number aim:** angle is integer degrees (0 = right, 90 = up), power
  integer percent. Matches the ±1° / ±1 % fine controls and keeps inputs
  exact for replay.
- **Deterministic trig:** `lib/sim/trig.dart` builds a 360-entry sine table
  with a Taylor series (only + and *), because libm `sin/cos` may differ
  between CPUs. `sqrt` is allowed (IEEE correctly rounded).
- **Integrator:** semi-implicit Euler per tick, in px/s and px/s² units.
  Starting values in `lib/config/physics.dart`: gravity 500, max launch speed
  900, wind 12 px/s² per wind unit.
- **Collision sampling:** the projectile is a point; each tick's segment is
  sampled at ≤ 1 px steps, and the first tick also tests the launch point.
  The visual is a 12 px circle so it stays visible at whole-map zoom.
- **Out of bounds:** leaving left, right or bottom removes the projectile with
  no explosion; flying above the top is allowed. Hard cap of 30 s per flight.
- **Chunk re-render uses `Picture.toImageSync`:** returns immediately and
  rasterises on the GPU thread, so no async queue or half-updated chunks.
  Initial chunk build uses `decodeImageFromPixels` straight from the mask.
- **Chunk draw paint has antialiasing off;** with it on, scaled chunks showed
  1 px seams at the 256 px borders.
- **Crater edges have no grass/rim yet** (pure `BlendMode.clear`). Revisit in
  M5 polish.
- **Test bench inputs** (`DebugExplode`, `DebugFire`, fixed launcher) were
  removed in M2 in favour of units and real inputs.
- **Explosion timing readout** (debug/profile builds only) measures sim step
  (mask carve) + chunk re-render scheduling on the main thread. Web debug
  showed 2–8 ms, which says nothing about Android; measure on the test device
  in profile mode.
- **Placeholder map** is generated by `tool/gen_sandbox_map.py` (stdlib only):
  plateau under the launcher, 3 px wall (tunneling check), floating island,
  cave, low edges under the water line.
- **Web is a visual smoke test only.** The sim's 32-bit integer math relies on
  native 64-bit ints, so results on web are not deterministic (web is a
  non-goal). `.claude/launch.json` serves `build/web` for that preview.

## M2 — Units and turns (2026-10-18)

- **Unit body is a 1 px column** 24 px tall standing on its feet pixel
  (`lib/sim/unit.dart`); hits and blast distance use a 12 px circle around
  the body centre. Simple, deterministic, and matches the climb rule.
- **Walking:** 1 px steps; climbs up to `maxClimb` (6 px), follows slopes
  down by as much, walks off anything steeper. Same code will drive
  Bebek Peledak / Seruduk in M3.
- **Jumps:** forward 160/240 px/s, high 40/300 px/s. Peaks ≈ 58 / 90 px,
  kept under the 120 px fall threshold so a plain jump never hurts
  (a playtest in the browser caught 380 px/s doing 3 damage).
  (Resolved in M3: jump passives raise the fall threshold, see below.)
- **Fall damage** is measured from the highest point of the airborne
  stretch to the landing, for jumps, ledges and knockback alike.
- **Blast distance** is from the explosion centre to the *edge* of the unit's
  hit circle, so a blast that visibly overlaps a unit always hurts it.
- **Knockback:** 9 px/s per damage point, along centre → unit plus an upward
  lift of 0.5 (otherwise ground blasts only slide units sideways).
- **Death timing:** water and leaving the map kill at once; HP ≤ 0 deaths
  are resolved in the settle step, right before the winner check (PRD).
  A unit at 0 HP can still be knocked around until then.
- **Turn phases** (`lib/sim/turn_manager.dart`): banner (90 ticks, no input)
  → action (turn clock) → retreat (3 s, starts the moment you fire, while
  the shot is still flying) → settling (projectiles gone and every unit
  grounded, 20 s safety cap) → next turn or match over.
- **Turn order:** teams in setup order; within a team a per-team cursor gives
  each living unit a turn in roster order. Dead units are skipped.
- **Wind** rolls at the start of every turn from the sim RNG.
- **Projectiles reaching the water line sink** without exploding.
- **Shots start just outside the shooter's hit circle** (shared helper
  `SimWorld.launchOrigin`, also used by the aim guide). Shooting straight up
  can still hit yourself — friendly fire is on.
- **Spawning:** topmost ground only (no caves), flat within ±3 px over
  ±8 px, above water, ≥ 150 px apart; relaxes flatness then distance if a
  map is crowded. A test checks the sandbox map fits 16 units for 20 seeds.
- **Match seed** comes from `Random()` in the UI layer (never in the sim),
  printed with `debugPrint` and shown in debug/profile builds.
- **Controls:** one finger drags the slingshot when the unit may fire,
  otherwise pans; two fingers always pan + pinch (a second finger turns an
  aim drag into a camera gesture and restores the previous aim). Dragging
  back into the 16 dp dead zone cancels. Fire and fine ±1 controls appear
  only while aiming. Walk buttons use raw pointer events (no tap delay).
- **Camera:** zoom 0.5–2 where 1 = one world px per dp; default 1 (raised
  to 1.4 in M3). Follows a
  projectile in flight, centres on the new active unit each turn, and nudges
  back when the active unit moves out of the middle half of the screen.
  Standing still never moves it, so players can look around.
- **Angle/power readout next to the unit** shows only numbers and symbols,
  so it is drawn in Flame without an ARB entry.
- **Turn banner sits in the upper third**, not centred: the camera centres
  the active unit, so a centred banner hid it.
- **Placeholder units:** cream body, team-colour outline, eye on the facing
  side, HP in team colour above. Family shapes and breed colours: M3.
- **Dev match:** the main menu starts 2 teams × 2 units (`DevMatch` in
  `lib/config/controls.dart`) until the setup screen (M4).
- **Result card** is a minimal overlay; the full results screen and the
  back-gesture pause dialog are M4.
- **Acceptance test:** `test/game/full_match_test.dart` plays three 2×2
  matches on the real map with a brute-force bot and checks each ends with
  exactly the winner's units alive.

## M3 — Weapons and families (2026-10-18)

- **Weapons are compositions of reusable parts** (`lib/config/weapons.dart`):
  an aim mode (angle+power, direction, none, target), a delivery (launch,
  air strike, place mine, area hit, dash, teleport, build wall, skip,
  walker), a flight behaviour (ballistic, bouncy, boomerang, drill) and an
  impact (explode, split, scatter mines). Behaviours live in
  `lib/sim/weapon_behaviors/` behind a small `SimContext` interface, so the
  same code serves several weapons (Bom Cluster and Hairball both use
  `Split`; Ranjau and Biji Ranjau share the mine system; Bebek Peledak
  walks with the unit walking code; Pukulan and Kokok Kejut are both
  `AreaHit`).
- **Passives are parameters only** (`PassiveDef` in
  `lib/config/families.dart` → `UnitStats.forFamily`). No code branches on
  a family id; rendering picks a `PlaceholderFeature` from data.
- **Jump passives raise the fall threshold** by the extra height they
  allow (Kelinci's 2× high jump, Ayam's extra mid-air jump), so a jump
  never hurts on its own landing. Found by tests: an unadjusted Ayam
  double jump cost 13 HP on flat ground.
- **Kucing's save is spent on the lethal hit itself.** If the same blast's
  knockback then causes fall damage, that can still kill — the save is
  "once per match", not "once per event".
- **Bebek's water save** puts the unit on the nearest dry topmost ground
  (scanning outward column by column) and costs 25 HP as `water` damage.
- **Kura-kura's −25 %** applies to explosions only, not to direct hits
  (punch, shockwave, boomerang, headbutt) or falls.
- **Numbers the PRD left open**, all in config: hairball bombs 20 / r25;
  bone 30 per hit, range 150–500 px by power, 500 px/s; drill 300 px/s,
  tunnel r10, final blast 25 / r25; eggs 25 / r30, 40 px apart; seed mines
  25 / r30; Bebek Peledak 40 / r40, walks 90 px/s, hops walls; headbutt
  600 px/s, digs r12; Benteng wall centred on the tapped point; grenade
  restitution 0.5; cluster bomblets 15 / r20.
- **Granat Pantul** bounces off ground (normal estimated from nearby
  mask pixels) and units, comes to rest on floors, and only explodes on its
  fuse (1–5 s, chosen in the HUD, clamped in the sim).
- **Tulang Bumerang passes through terrain** and hits each unit at most once
  per leg; the thrower is never hit.
- **Mines:** armed from the next turn ("aktif setelah 1 giliran"), trigger
  when a unit's centre comes within 30 px, explode 0.5 s later. Any blast
  in range sets them off at once (chains). A mine can hurt its owner.
- **Teleport** targets the body centre, needs empty space there, ends the
  turn immediately (`endsTurn`), and the unit falls if placed in mid-air.
  An invalid target is refused without using ammo.
- **Benteng** may not overlap a living unit and must fit on the map; added
  ground is redrawn by rebuilding the touched chunks from the mask
  (versioned so a rebuild still decoding is redone if carved meanwhile).
- **Ammo** is per team per match (shared weapons); signature weapons are
  once per unit. Sub-munitions are `hidden` and can never be fired.
- **Ketapel Ganda's second shot** is scheduled 20 ticks later from the
  shooter's current position; a settle timeout drops pending shots.
- **L10n keys from config:** `tool/gen_l10n_lookup.py` generates
  `AppLocalizations.byKey()` from `app_en.arb` (run by `tool/ci.sh`); a test
  checks every config `nameKey` resolves in EN and ID. Breed names are
  identical in both languages (PRD).
- **Dev match:** the main menu now starts 2 teams × 3 units with random
  families and breeds, derived from the match seed (until setup in M4).
- **HUD:** weapon button opens a grid with ammo (∞ / ×n), signature tile
  outlined and marked "Signature"/"Used". Controls adapt to the aim mode;
  thrown weapons say "Fire", others "Use". Target weapons are picked with a
  tap (green / red crosshair), one-finger drag pans while one is selected.
- **Placeholder units** got a thin dark edge on the family feature (pale
  breeds vanished against the sky) and the default zoom went to 1.4 so a
  24 px unit reads on a phone.

## M4 — Screens and full flow (2026-10-18)

- **Flow:** splash (loads settings) → main menu → setup → arena → results.
  Results replaces the arena, so "Change teams" is just going back to the
  setup screen; "Main menu" pops to the root.
- **Back gesture in the arena opens the pause menu** (`PopScope`, plus
  `android:enableOnBackInvokedCallback` for predictive back). Pausing stops
  the Flame engine, so the turn clock freezes. Settings opened from pause
  apply the aim-guide switch when you come back. Exit asks for
  confirmation; dismissing the pause menu resumes.
- **Setup is saved on Start** and restored next time; data that no longer
  matches config (removed breed, bad value) falls back to defaults instead
  of crashing (`MatchConfig.fromJson`).
- **Team colours:** 6 to choose from; picking a colour another team has
  swaps them. A team with no custom name shows its colour's default name
  ("Tim Merah"), so the name follows the colour.
- **Random names** come from the `unitNamePool` ARB entry (comma-separated),
  different per language, so even generated text lives in ARB.
- **Random map** is resolved from the match seed when the match starts.
- **Sudden death:** starts with the first turn after the chosen minutes of
  match time (sim ticks, so it is deterministic): every unit → 1 HP. Then at
  the end of each round (one turn per surviving team) the water rises
  20 px and immediately drowns whoever it reaches (Bebek can still be
  saved once) before HP deaths and the winner check. Same-rise wipe = draw.
- **Damage attribution:** `UnitDamaged.sourceUnitId` (weapon owner; null for
  falls and water). Results count only damage to enemies; a knockout is
  credited to the team that last hurt the unit.
- **Maps:** Backyard, City Park, Old Warehouse, generated by
  `tool/gen_maps.py` from simple original shapes. Each is tested to fit 16
  units on flat dry ground for 20 seeds. The M1 sandbox stays only for
  tests.
- **About:** version from `AppInfo.version` (no package_info plugin — not in
  the PRD list; keep it in sync with pubspec). Credits are read from
  `assets/CREDITS.md` at runtime. The privacy URL is shown with a copy
  button because opening links needs `url_launcher`, which is not allowed;
  the URL itself is a placeholder until M6.
- **Unit names** float above HP in the arena; the placeholder look is drawn
  by one shared `UnitPlaceholderPainter` for the arena and Flutter screens.
- **Layout bugs caught by widget tests:** the main menu's button column was
  stretching and pushed About below a 393 dp-tall landscape screen; the
  team-colour row could overflow narrow phones (now wraps). A test opens
  every screen in Indonesian at 873 × 393 dp and fails on any overflow.
- **Settings stored but not yet used:** music/effects volume and vibration
  are saved now and wired to audio and haptics in M5; "show the tutorial
  again" resets a flag the M5 tutorial will read.

## M5 — Polish (2026-10-18)

- **Particles are one pooled component** (`lib/game/effects/particle_system.dart`):
  800 slots in typed arrays, swap-remove on death, no object per particle,
  dropped when full. Explosions (flash, debris in the map's dirt colour,
  sparks, smoke), rings for shockwaves/punches, dust on hard landings and
  digging, splashes when anything hits the water. Visual only: its own
  unseeded RNG, never read by the sim.
- **Projectile pooling:** rendering already has zero objects per projectile
  (one component draws the sim list). The sim's `Projectile` objects are a
  handful per turn, so pooling them would add risk to determinism for no
  measurable gain; revisit only if profiling shows GC from them.
- **Audio** (`lib/services/audio_service.dart`) maps sim events to the PRD
  sound list and loads files by name from `assets/audio/` (README there).
  Missing files are silent and never touch the audio plugin, so the build
  works with no audio at all. The same sound plays at most every 60 ms
  (cluster blasts). Music switches menu ↔ match; volumes follow Settings
  live.
- **Haptics** use Flutter's `HapticFeedback` (no extra package or
  permission): light on firing, medium/heavy on blasts (≥ 50 px radius),
  at most one per 80 ms, off when Settings says so.
- **Tutorial:** four tooltips (walk → weapons → aim → fire) that advance
  when the player does the thing; doing a later step skips earlier ones.
  Only in the first turn of the first match (PRD), skippable; finishing or
  skipping sets the flag Settings can reset.
- **FPS readout** (debug/profile only): average fps and worst frame per
  half second, next to the explosion timing, for checking the PRD targets
  on the test phone.
- **HUD publish only after a sim step:** on 90/120 Hz phones there are more
  frames than ticks; the HUD only shows sim state, so the extra frames now
  skip that work.
- **Crash soak test** (`test/game/soak_test.dart`): a bot plays 20 full
  matches across all 3 maps with 2–4 teams, 1–4 units, random families and
  random usable weapons (all 17 non-skip weapons get used), with sudden
  death so every match ends. Checks that each ends with only the winner
  standing. This covers the sim; crash-free UI over 20 matches still needs
  the device run.
- **Performance targets need the test phone** (60 fps, ≥ 50 during
  cluster blasts, explosion < 4 ms, cold start < 3 s, < 300 MB, < 50 MB
  download). The readouts are in place; numbers to be filled in from a
  profile-mode run.

## Visual pass (2026-10-18)

Player feedback: UI and art felt unfinished (letters for animals, no
weapon visuals, plain maps). Direction chosen by the owner: drawn in code,
semi-realistic rather than cartoon, system font kept.

- **Animals** (`lib/game/art/animal_art.dart`): side-view anatomy per family,
  gradient shading from one top-left light, darker far legs for depth,
  contact shadow, breed coat patterns clipped to the body, team collar,
  idle/walk/air poses. Each (breed, team, pose) is recorded once into a
  `Picture`; the arena only replays and transforms it. Visuals are a bit
  larger than the 24 px hit circle, like most artillery games.
- **Breeds** gained a marking colour, a `CoatPattern` and long fur; still
  purely cosmetic.
- **Weapons** (`lib/game/art/weapon_art.dart`): shaded art for every
  projectile, mines and all menu icons (same code paints both).
- **Map materials:** each ground pixel has a material (soil, wood, leaves,
  stone, metal, crate, concrete) in the map PNG's red channel (green = 200
  marks it). Render only; the sim still reads alpha, so gameplay and
  determinism are unchanged. Benteng walls render as stone.
- **Terrain texture** restarts its depth where the material changes, so
  objects don't cast "shadow columns" into the ground under them.
- **Craters** get a burnt rim drawn with `srcATop` (only on remaining
  ground); tunnels and dashes don't.
- **Scenery:** per-theme parallax layers (0.2–0.65 of camera speed) with
  atmospheric haze, a sun glow, soft drifting clouds; animated water;
  surface decorations that vanish when their ground is destroyed. All
  visual-only randomness is seeded from the map id, never the sim.
- **UI theme:** the first dark "glass + amber" theme was rejected by the
  developer as generic (see "Field guide identity" below); replaced.
- **Gallery test:** `RENDER_GALLERY=1 flutter test test/art/gallery_test.dart`
  writes PNGs of every breed, weapon and map to `build/gallery/` for quick
  art review; without the flag it still smoke-tests every painter.

## Field guide identity (2026-10-18)

The developer compared the UI with Stillroom and found it generic. The
difference was identity, not polish: Stillroom has a one-line concept, a
named palette with meanings, a period typeface, UI built as objects of its
world, square hairline shapes, an atmosphere layer and restraint.

- **Concept chosen:** "A naturalist's field journal that went to war."
  Written up in `docs/art_style_guide.md`, which every screen now follows.
- **Type:** Old Standard TT (SIL OFL), copied from the developer's own
  Stillroom assets with its licence (no download), one weight, titles in
  spaced capitals, Latin names and asides in italic.
- **Palette** (`lib/app/field_palette.dart`): paper, ink, pencil, one stamp
  red that means "do it" or "it hurt"; team colours became printer's inks.
- **Kit** (`lib/ui/widgets/field/`): paper atmosphere (fibres, specks, warm
  vignette), paper panels with tape and double rules, leaf rules, rubber
  stamp buttons (always on paper so they read over the scene), table of
  contents entries, ink-drawn icons (no Material icons on screen),
  engraved plates (the colour art run through an ink/paper duotone
  matrix), catalogue sheets, specimen tags, tally marks.
- **Screens:** main menu as a journal spread; setup as a field roster with
  catalogues of plates instead of dropdowns; How to Play as journal pages;
  Settings as a printed form; About as a colophon; results as a field
  report with the winner stamped in the team's ink; pause and confirm as
  taped paper sheets; the weapon menu as a catalogue of arms.
- **Arena:** the world stays painted in colour; only the HUD is paper and
  ink (turn slip, wind scale, hatched HP tally, paper tokens, Fire seal).
  Unit tags use the book face with HP in the team's ink.
- **Copy voice:** no exclamation marks in UI chrome ("Sudden death",
  "A draw", "Observed over 17 turns").

## "Sunny Brawl" painted-cartoon redesign (2026-10-18)

The developer found the field-guide look too close to Stillroom and asked
for the quality of Worms W.M.D across menus, widgets, maps and animals.
The PRD forbids using another game's names, characters, assets or text, so
we matched the *quality bar and genre conventions* (painted cartoon,
chunky UI, set-piece maps, name/HP labels over units, crosshair, juicy
explosions) with our own identity. The developer chose: painted-cartoon
animals, a downloaded bold font, and new map themes.

- **Identity:** "A Saturday-morning cartoon brawl on a sunny farm",
  written up in `docs/art_style_guide.md` (replaces the field guide),
  including a "theirs / ours" table of what is not borrowed.
- **Type:** Lilita One (SIL OFL, from Google Fonts), one weight, replacing
  Old Standard TT. Outlined text is built from text shadows so it stays one
  Text widget.
- **UI kit** (`lib/ui/widgets/toon/`, palette `lib/app/toon_palette.dart`,
  theme `lib/app/toon_theme.dart`): slab buttons that sink when pressed,
  round icon buttons (also hold-to-walk), cream and night panels, ribbon
  titles, segmented chips, switches, picker tiles, code-drawn outlined
  icons, a painted meadow backdrop and a bouncing wordmark. The field kit
  was removed. Button labels are upper case; UI tests were updated.
- **Team colours** are bright (red, blue, green, yellow, purple, orange)
  so labels read over any map.
- **HUD:** pause and focus buttons, a team-coloured timer badge that turns
  red and pops in the last 5 s, a wind meter, glossy team HP bars, a night
  weapon card, big round Fire button; the weapon menu slides in from the
  right; the turn banner is a team ribbon below the centre (the top holds
  the HUD). Unit labels are name and HP on two translucent boxes in team
  colour with an outline; the active unit gets a bouncing arrow; aiming
  shows a team-coloured crosshair whose ring fills with power.
- **Animals:** redrawn in `AnimalArt` with the same API: big heads and
  eyes (pair of eyes, highlights, brows), dark outlines on every part,
  cel shading via a path-difference shadow crescent, team bandana with
  polka dots. Label height 36 → 37.
- **Maps:** backyard/park/warehouse replaced by Sunny Farm, Lighthouse
  Cliffs and Snowcap Peak (`tool/gen_maps.py`): a hollow barn with a loft,
  haystacks, a pond, burrows, an orchard tunnel, a water tower; a cliff
  with a sea cave and a hollow lighthouse, sea stacks, a rock arch, a pier
  and a sandy beach; a peak with a tunnel, an ice cave, a snow cornice, a
  frozen lake with a breakable ice sheet, a log cabin and pines. Material
  encoding widened to R = material × 16 + 8 (16 materials); new materials
  hay, roof, sand, rock, ice, snow. `MapDef` gained `cap` (grass/snow) and
  `baseMaterial`; `TerrainStyle` was removed. Saved setups that name an
  old map fall back to defaults (existing validation).
- **Terrain painting:** dark outline at every air edge (also around new
  craters), grass or snow cap with a shadow line, lit rims, stretched
  value-noise brush strokes, light posterisation, per-material textures.
- **Backdrops:** farm fields with barns and silos and outlined lollipop
  trees; a sea horizon with islands, boats and gulls; snowy peaks and pine
  belts with snowfall. Clouds are puffy cartoon clouds as on the menus.
  Decorations depend on the material (shells and starfish on sand, snow
  clumps in the mountains).
- **Effects:** flash, additive fireball that runs yellow → red, embers,
  sparks, outlined debris in the colours of the ground that was hit, and
  a smoke column that lingers ~2–3 s. Pool capacity 800 → 1400.

## Closer to the W.M.D look, still code-drawn (2026-10-19)

The developer asked for terrain and characters that look really like
Worms W.M.D, without image assets. Research (Team17 interviews: hand-
painted landscapes vs. simpler clean-lined characters, kept different so
scenery and interactive things read apart; simple clear backdrops) gave
the principle we adopted; we do not copy their characters or art.

- **No image assets:** an untracked bitmap pipeline that had appeared in
  the repo (`art/`, `assets/art/`, `lib/config/art.dart`,
  `lib/game/art/art_library.dart`, unreferenced and not compiling) was
  moved out of the repo to `../pawtillery_unused_art/`, not deleted.
- **Terrain:** the hard dark outline became a soft crust; grass blades
  and snow lumps are painted into the air above caps, roots/leaves/icicles
  hang under overhangs (visual only, the mask is unchanged); warm/cool
  colour drift and wandering strata; lighter posterisation. Rock is now
  stacked boulders and leaves are lit clumps (Worley cells) instead of
  noise cracks.
- **Backdrops:** outlines removed from background trees, fields and
  peaks; trees hazier.
- **Animals:** heavy upper eyelids in the head colour (brows removed),
  eyes 12 % bigger, outline 1.15 → 1.35, fainter highlight, long fur as
  one merged silhouette.
- **Gallery:** each map also renders a close-up at the arena's default
  zoom (`build/gallery/map_<id>_close.png`).

## "Dusk Brawl": moody maps, smooth terrain, real water (2026-10-19)

The developer found the sunny look wrong for a war, the terrain
pixelated, the props not sitting on the ground, and the water flat; they
asked for spooky places like a castle or the sea, like W.M.D, still with
no image assets.

- **Why it looked pixelated:** terrain pixels were 1 world px drawn
  without filtering (to hide chunk seams) at 1.4× zoom on a dense
  screen. Now edge pixels get coverage alpha, chunks carry a 2 px gutter
  and are drawn with bilinear filtering from their inner rect: smooth,

## Play on Wi-Fi: local-network multiplayer (2026-10-20)

The developer asked whether multiplayer over Bluetooth was possible. We
recommended the same Wi-Fi network (a router, or one phone's hotspot)
instead, and the developer approved the plan. This extends the PRD, which
covered hotseat only; hotseat is unchanged.

- **Why Wi-Fi, not Bluetooth:** `dart:io` sockets need no new package
  (Bluetooth would need a plugin outside the PRD list), Wi-Fi has more
  range and bandwidth, and 3–4 phones work as easily as 2. Nothing goes
  to the internet; the privacy note ("collects no data") still holds.
- **Lobby:** the host opens a room (TCP, port 47821 or any free one) and
  broadcasts a UDP beacon to port 47820 every second: to
  255.255.255.255, to each interface's /24 broadcast address (a phone
  hotspot often doesn't route the limited broadcast onto its own network,
  and Dart doesn't expose netmasks), and to loopback. Guests list the rooms
  they hear, or join by typing the host's IP (shown in the lobby), for
  networks that block broadcasts. Up to 4 phones. The host edits the
  setup with the normal Setup screen and hands each team to a player;
  a phone may control several teams or none (watching).
- **Protocol** (`lib/net/protocol.dart`): JSON lines, versioned. Guests
  with another protocol version or app version are turned away, since a
  different build may have different balance. The host picks the seed and
  the map (a random map is never picked on each phone) and sends the full
  setup, weapons included.
- **Lockstep** (`lib/net/lockstep.dart`): every phone runs the same
  `SimWorld`. Only the phone that controls the active team produces input
  frames, one per tick and 4 ticks ahead of its own sim, so it plays
  without lag. The host relays them, and the other phones step only once a
  tick's frame is there, catching up when they fall behind. When the turn
  passes to a team on another phone, the producer marks its last frame
  (`end`) and the next phone continues from the following tick. Every
  phone knows when that is, because the sim decides it, and inputs do
  nothing during the turn banner, so the hand-over costs no play time.
  We chose this over a host clock because the active player never waits
  on the network.
- **Desync check:** guests send `stateHash()` every 60 ticks and at the
  end; the host compares them with its own and stops the match for
  everyone on a mismatch.
- **Disconnects:** each link pings once a second and counts as lost after
  6 s of silence (a phone that walked out of range sends no FIN). A lost
  guest pauses the match for everyone and the host can end it. If the host
  is lost, the guests see a message and return to the menu. Reconnecting
  in the middle of a match is not supported yet.
- **In the arena:** the pause menu doesn't stop a Wi-Fi match. Other
  phones see "{name}'s turn" instead of the controls, and "Waiting for
  {name}…" after a second without a step. There is no tutorial. The
  results screen goes back to the lobby instead of offering a rematch.
- **Platform:** Android gets `INTERNET`, `ACCESS_WIFI_STATE` and
  `CHANGE_WIFI_MULTICAST_STATE`, plus a small `MainActivity` method
  channel that holds a `WifiManager.MulticastLock` while the Wi-Fi screens
  are open, because many phones drop broadcast packets without one. This
  is a few lines of platform code, not a package. The web has no
  sockets: `lib/net/lan.dart` exports a stub there, and the menu hides
  the option.
- **Tests:** protocol round trips, and lockstep matches with two and
  three phones through in-memory links (with dropped frames to exercise
  catch-up), all ending with equal hashes. Also a forced desync, rejected
  joins and lost players, plus one real-socket test on localhost (finds
  the room by beacon, joins over TCP, plays to the end).
- **Checked end to end** on two iOS simulators on one Mac (Android is
  the target, but the simulators can be driven by taps; both share the
  Mac's network). The guest found the room by its beacon, joined, saw the
  host's setup changes, and both played to the results. Both logged the
  same final state hash (`Pawtillery final state hash: …`, printed like
  the seed). Leaving as host showed "lost the connection" on the guest,
  and "Back to lobby" brought both back for another match.

## CPU opponents (2026-10-28)

The developer asked for computer opponents first, so the game can be
played alone on one phone (and playtested without a second person).

- **Setup:** each team card on the Teams tab has a picker: Player,
  CPU · Easy, CPU · Normal or CPU · Hard. It is saved with the setup
  (`TeamEntry.cpu`; older saves are players). Any mix works, CPU against
  CPU included. Play on Wi-Fi has no CPU teams: the picker is hidden in a
  Wi-Fi room and the host's saved setup is stripped of them.
- **Where it lives:** `lib/ai/`, pure Dart like the sim but outside it.
  The CPU is a player, not a rule: it only reads `SimWorld` and sends the
  same inputs a person would, so the sim, its hash and the Wi-Fi protocol
  are unchanged (no protocol bump).
- **Planning** (`CpuPlanner`): thrown weapons whose landing can be
  predicted (plain arcs, splits, fire, frost, gas, the nuke, sticky bomb)
  are flown with the real `ProjectilePhysics` over a 4° × 4 % grid, then
  1 × 1 around the best four spots. The best eight are flown again at the
  edges of the level's aim error and lose half of what they would lose
  there, so a shaky aim doesn't land on itself. Weapons that fly the same way share
  one search. Air support, lightning, the satellite and meteors are tried
  on each enemy, looking straight down that column for cover. Beams, the
  shotgun and punches try every direction; the first-aid kit and the
  crow's shockwave are scored in place. Bouncy, homing, drilling,
  boomerang, walking and building weapons, mines and movement tools are
  not used yet.
- **Score:** expected damage with the sim's own falloff and
  `explosionDamageScale`, +25 for a knockout, a popped shield counts 6;
  damage to its own team counts −1.6×, measured as if they stood 30 px
  closer to the blast. Limited ammo costs 8–18 points
  (more for the last shot), so the rock stays the everyday weapon. A
  small bonus for landing near an enemy keeps it shooting the right way
  when nothing is in reach.
- **A turn** (`CpuPlayer`): it plans during the turn banner, about 2 ms
  of search per tick so a frame never stalls (a long flight on a wide map
  with many pets costs far more than a short one, so it is timed). If the best plan is weak it walks up
  to 1.5 s towards the nearest enemy (stopping before a drop of 60 px or
  water) and plans again. It then pauses, swings the aim into place over
  0.7 s (or shows the target marker) so players can see it coming, and
  fires. The shot path is not drawn for CPU turns. Below 4 s on the turn
  clock it fires the best plan so far.
- **Levels** (`lib/config/cpu.dart`): Easy reads half the wind, aims up
  to ±5° / ±6 % off and only uses unlimited weapons and its signature;
  Normal reads the wind, ±3° / ±4 %; Hard ±1° / ±1 % and spends ammo
  more freely.
- **In the arena:** the controls give way to "{team} is thinking…", the
  same pill Wi-Fi uses for another phone's turn. The first-match
  tutorial only runs when a person plays the first turn.
- **Tests** (`test/ai/cpu_test.dart`): hits on flat ground with and
  without wind, no blast on its own teammate, same seed same plan, Easy
  keeps to unlimited weapons, walks when out of reach, and CPU against
  CPU matches on Backyard and Ruins end with a result.

## Wi-Fi: rejoining a match after a dropped connection (2026-10-28)

Before, one phone dropping out (Wi-Fi blip, out of range, screen locked
for a while) paused the match for good: the host could only end it.
Now the slot waits and the phone comes back on its own.

- **Who can rejoin:** a guest, while its app is still running. Its
  `WelcomeMsg` carries a random key; mid-match it reconnects to the same
  address (`redial`) every 2 s for up to 90 s and sends `RejoinMsg` (id,
  key, how many ticks it has). The host lets it in only if that slot is
  waiting, the key fits and the versions match; otherwise it says
  "started" and the guest tries again (the host may not have noticed the
  drop yet: links time out after 6 s). An app that was closed can't
  rejoin, and a lost host still ends the match once the 90 s are up.
- **What it gets:** both sessions keep the match's full input log (what
  they sent and received, `NetSession._log`). The host answers with
  `ResumeMsg(known)` and the ticks the guest is missing; a guest that was
  playing when it dropped may instead have ticks the host never got, and
  sends those. At equal counts the hand-over marker ("producer stopped")
  wins, so nobody is left waiting for a producer that already stopped.
  Because the sim is deterministic, that is all it needs: every phone
  ends on the same hash.
- **While waiting:** every phone pauses (as before) on `PlayerLeftMsg`;
  the host can still end the match. The dropped phone shows "Connection
  lost — reconnecting…" with a Leave button. `PlayerBackMsg` resumes
  everyone once nobody is away. A rejoining guest is also told who else
  is away.
- **Lockstep:** a phone starts producing for its turn only once it has
  stepped every known tick, so a guest catching up never takes one of
  its old turns for a new one.
- After the match the slots of guests still away are dropped from the
  lobby, as before. Protocol version 15.
- **Tests:** memory links with cuts in both players' turns, a link that
  goes quiet so the host really misses the guest's ticks, three phones
  waiting for one, refused rejoins, and one over real sockets on
  localhost. Not yet tried on two phones.

## Performance pass (2026-10-28)

No phone was connected, so this pass measured what the Mac can measure
(a throwaway benchmark: four teams of four Hard CPUs on Backyard and
Shipwreck, every tick timed) and read the drawing code for costs that
are known to hurt on phones. Profile-mode numbers from a real phone are
still the real test.

- **Decor** (tufts, pebbles, toadstools, shells, bones, rubble) drew
  every piece on the whole map each frame, built a fresh gradient paint
  for each pebble and cap, and wrapped it all in a screen-sized offscreen
  layer for the ambient light. Now the still pieces are recorded into one
  picture per 512 px of map (re-recorded only when a piece is blown
  away), only the swaying tufts are drawn live, only what is on screen
  is drawn, and the ambient light is a colour filter on each paint. The
  gallery renders look the same.
- **Terrain** chunks off screen are skipped (`PawtilleryGame.visibleWorld`,
  the camera's view plus a 64 px margin).
- **Projectile sweep** (`ProjectilePhysics.sweep`): it checked every unit
  at every 1 px sample. It now first checks whether any unit's hit circle
  touches the tick's segment box and skips the per-sample check if none
  does (most ticks of a flight). Same results exactly; the pinned hashes
  didn't change. This serves the sim and the CPU planner alike.
- **CPU planning** was sliced by a count of flights per tick, but one
  flight can cost a hundred times another (near-weightless shots skimming
  a wide map with 16 pets). It is now sliced by time, about 2 ms a tick,
  and a planned flight stops after 6 s or once 600 px above the map.
  Before: single ticks of 40–240 ms while a CPU thought; after (debug
  JIT on a Mac, after warm-up) 99 % of ticks take under 2.2 ms, sim and
  planning together, with rare spikes that look like garbage collection.
- The worst sim tick (a nuke carving the ground) measured 2–5 ms in the
  same debug JIT setting; release builds run several times faster.

## Wi-Fi: rejoining after the app was closed (2026-10-29)

The developer wanted a guest to come back even if its app was closed
(swiped away, killed by the system) during a Wi-Fi match.

- **Ticket:** when a match starts, the guest keeps a `RejoinTicket` with
  the settings (host address and port, its player id, its key, its name).
  It is dropped when the match ends, is called off, the guest leaves, or
  the host is given up on.
- **Offer:** on launch, if a ticket is there, the main menu asks "Match
  still running — go back?". "Forget it" drops the ticket; "Go back" opens
  the Wi-Fi screen, which rejoins (`GuestSession.rejoin`, a `RejoinMsg`
  with `fresh`). If the host no longer waits for that player the ticket is
  dropped with a short message.
- **Host:** for a fresh rejoin it sends the `StartMsg`, then every tick of
  the match so far, then `ResumeMsg` (missed ticks now always come before
  the resume, so a guest has them the moment it is let in). The lobby
  opens the arena at once.
- **Catching up:** the arena replays the match with the same lockstep,
  but while far behind (over 240 ticks) it fast-forwards — as many ticks as
  fit in 10 ms a frame, without sound, particles, damage numbers or camera
  jumps; the ground is still carved — and shows "Catching up…".
- **Its own turn:** if the app was closed in the middle of its own turn,
  no one will ever hand that turn over (the phone playing it is gone).
  `Lockstep.resumeOwnTurn` lets the rejoined phone carry on from the last
  known tick if the turn is still its own there; no frame of the old app
  can still be on its way.
- Tests: a guest killed mid-match (in its own turn) rejoins from its
  ticket and both phones end on the same hash; a stale ticket is refused;
  the menu offer. Protocol version 17. Not yet tried on two phones.

## The CPU uses every attacking weapon (2026-10-29)

The developer asked why the CPU left so many weapons alone. It only
predicted plain arcs. Now weapons whose flight isn't an arc (grenade,
sniffer rocket, bottle rocket, coconut, bone boomerang, drill carrot,
seed mines) are run with their real `FlightBehavior` in a shadow of the
world (`_PlanContext` in `lib/ai/cpu_planner.dart`): it reads the real
ground and pets but carves nothing, adds no ground, moves no pet and has
its own random numbers, and it adds up what the blasts, hits, fire, gas,
frost and mines would do. Shots are built by `SimWorld.shotFor`, shared
with the sim, so a planned throw is the real one. These are searched on
a coarser grid (8° × 8 %, then finer around the best three).

- The black hole is rated where it lands (it pulls pets in, which the
  shadow can't do without moving them); the headbutt by the first pet
  in its path; the walking duck is run for real left and right; the
  firecracker is set down and the CPU then runs the other way in the
  retreat (mines too); the shield when it is hurt and nothing better is
  on. Tools for moving and building (teleport, grapple, dig, clay,
  fortress, swap) are still left to people.
- A probe with every weapon unlimited showed the new flowerpot stack too
  strong (five pots on one spot, up to 80 damage, no aim needed, picked
  67 times): 16 → 10 a pot.
- Plans take longer in a debug build (about 75 ms on average, still

## Sound effects off the Android main thread (2026-10-29)

A profile run on the developer's phone (Galaxy A55, 120 Hz) logged the
Android main thread stalling again and again ("Skipped 40–178 frames",

- Vibration still goes through Flutter's haptics on the main thread;
